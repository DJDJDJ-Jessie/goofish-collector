# 闲鱼公开商品研究采集器｜产品文档

版本：0.5.8
日期：2026-08-08
产品状态：开发中

## 1. 产品定位

这是一个面向商业计划书、可研报告、标书和调研报告工作的“公开商品研究采集器”。它帮助用户把闲鱼上已经公开展示的商品详情、图片、价格、类目、商品文案以及店铺公开信息整理成可分析的 Excel 文件。

产品的核心承诺是：搜索页只负责发现商品，最终商品结果必须来自逐个打开的商品详情页；商品结果和店铺结果分开管理；图片必须下载并嵌入 Excel，而不是只留下图片 URL。

## 2. 目标用户与使用任务

### 目标用户

- 需要研究“商业计划书、可研报告、标书、调研报告”等服务商品的个人或小型团队。
- 需要比较同行商品标题、卖点、价格带、图片风格、店铺包装和评价表达的人。
- 不希望编写脚本、处理 Cookie、拼接接口签名的非技术用户。

### 典型任务

1. 打开一个同行商品详情页，采集公开资料并选择加入商品总表或单独导出。
2. 打开一个同行店铺/账号页，采集店铺资料、全部已加载公开评价和评价图片。
3. 粘贴一批商品详情链接，插件在后台专用标签页中逐个打开并采集。
4. 在搜索结果页设置“最多 100 个商品、最多 5 页”，插件自动发现链接、逐个打开详情页、跨页继续，并在结束后提醒用户。
5. 选择接口观察模式，在商品详情页已公开加载的数据响应中提取字段，再导出同样的商品 Excel；接口观察不会绕过页面，也不会主动调用隐藏 API。
6. 选择自动下载或手动下载；在设置里调整文件名模板、图片数量和下载子目录。
7. 从历史任务里查看、重新导出或删除已经完成的采集结果。

## 3. 功能范围

### 3.1 当前详情页

- 仅允许在商品详情页执行最终采集。
- 详情页识别到的内部字段包括：商品 ID、标题、商品文案、价格、类目、商品链接、图片、店铺名、卖家账号页链接、卖家地区、开店/来闲鱼时长、商品好评率、店铺评价数和采集时间。
- 导出的“商品数据”主表固定为以下 18 列，且不再导出商品标题、图片状态、来源页面、数据来源等辅助字段：

  `商品ID → 商品链接 → 主图文件名 → 商品图片 → 商品文案 → 价格 → 类目 → 店铺名称 → 卖家账号页 → 卖家地区 → 粉丝数 → 关注数 → 卖家商品数 → 店铺简介 → 开店时长 → 商品好评率 → 店铺评价数 → 采集时间`
- 详情页采集完成后会复用当前商品标签页进入卖家账号页，读取基础店铺字段后返回商品详情页；不会创建额外的卖家标签页。结果先进入本次暂存区，用户可以点击“加到数据中心商品表”合并商品结果，或点击“导出当前详情页”只下载当前结果；完整店铺资料和公开评价仍通过“采集当前店铺页”单独采集。
- 页面出现居中的公开登录提示时，采集器只尝试点击关闭按钮或安全的遮罩空白处，不填写手机号、不扫码、不读取登录凭据；提示消失且详情页关键内容稳定后才开始读取。页面尚未稳定时应重试或明确失败，不能把骨架屏、登录提示文字或空数组当作商品字段。
- 当前详情页只有在收到至少一条真实可导出的商品结果后才显示成功并启用“加到数据中心商品表”“导出当前详情页”。补采集账号资料导致同一标签页临时换页、返回后跟踪参数变化，都不能把已暂存结果和按钮状态清空。
- 商品页卖家入口按页面真实结构发现：优先从卖家昵称节点向上找到父级 `/personal?userId=...` 链接，再从带卖家统计信息的个人页链接中兜底；商品接口没有直接返回 `sellerUrl` 时，仍会向当前详情页查询入口后再进入账号页。
- 类目只有一个字段：服务类商品优先读取详情属性区的“服务类型”（例如“金融”）；详情属性标签即使被拆成多个字符节点也必须合并后再识别。不会因为不同商品的属性图片布局不同而额外制造图片类目字段；只有 URL 内部 `categoryId` 而没有公开名称时，类目留空。
- 账号页字段按字段所属区域读取，而不是按页面中出现的数字格式猜测：昵称、地区、粉丝/关注位于同一个账号资料容器，商品数/评价数位于对应 Tab，简介只来自账号资料区的简介节点。账号页异步渲染时会等待语义字段快照稳定后再合并；店铺简介即使是纯数字也属于合法公开文本，不会被导出层擅自清空。
- 详情 DOM、接口响应和二次扫描合并时，空值不能覆盖已识别值；语义类目优先于平台内部编号。字段识别必须在所属语义区域内完成：店铺简介允许是纯数字，但不能把粉丝、关注、访问时间或开店时长错填到简介；开店时长必须匹配“来闲鱼/开店/入驻/经营”标签和值的直接关系。
- 采集前显示当前页类型；搜索页点击当前页采集时给出明确提示，不静默失败。

### 3.2 当前店铺页

- 首页提供“采集当前店铺页”入口，只有当前页面识别为 `/personal?userId=...` 账号/店铺页时按钮可用。
- 采集前会尝试进入“信用及评价”区域；如果评价列表采用懒加载，插件会自动滚动并等待列表稳定。
- 店铺评价读取完成后，当前店铺页直接提供“立即下载 Excel”和“查看数据中心”两个入口，不要求用户返回首页寻找下载入口；店铺导出是独立工作簿，所有店铺资料、店铺评价和评价图片数据合并到“店铺综合”一张数据表，另附说明页，不带商品主表或历史商品链接。如果当前账号页已有历史记录，页面必须显示“历史已采集”、评价数量和最近采集时间，重新采集后明确显示首次保存或历史更新。
- “店铺综合”表一行对应一条公开评价，并重复带出店铺名称、卖家账号页、地区、粉丝、关注、商品数、简介、开店时长、好评率、店铺评价数、采集时间、来源页面和已采集评价数；无评价时保留一行店铺资料。
- “店铺综合”表同时保存评价序号、评价人、身份、评价内容、评价时间/地区、评价图片数、评价图片文件名、评价图片状态、评价图片失败地址和评价采集时间。评价图片的真实二进制嵌入同一行的“评价图片”列；头像和好评徽章不作为买家上传评价图片，带有评价图片区标识的原图优先保留。
- 如果页面只显示好评数量而没有直接百分比，店铺页的好评率按“好评数 / 店铺评价数”计算，并在导出说明中保留该语义；商品详情页的商品好评率优先使用详情页直接展示的百分比。

### 3.3 批量商品链接

- 支持文本框粘贴多条链接，空格、换行或逗号分隔。
- 自动去重，只接受闲鱼商品链接。
- 插件创建一个专用后台标签页，逐个导航到详情链接。
- 每次导航后先处理公开登录提示并等待商品 ID、价格/文案或详情主体等关键内容稳定，再执行采集；不能只依据浏览器的 `complete` 状态立即读空页面。
- 每个链接最多重试两次；失败链接保留在任务结果中。
- 每个详情链接采集完成后，任务会在同一条任务标签页进入卖家账号页补充基础店铺字段，再回到下一条商品；任务完成后提供“加到数据中心商品表”和“导出本次商品数据”两个按钮。最后一条商品也必须执行完店铺补采集才允许任务结束。
- 用户关闭专用标签页时，任务被标记为已停止，已经采集的数据保留。
- 批量任务暂存结果与数据中心商品总表隔离；只有点击加入按钮后才合并进入总表。

### 3.4 搜索页跨页详情采集

- 用户只需在搜索结果页启动一次，不需要手工逐条点击。
- 每页先发现商品详情链接，再逐个导航到详情页采集。
- 待访问顺序以可见卡片的屏幕坐标为准：先按纵坐标从上到下，同一排再按横坐标从左到右；滚动加载出的后续卡片追加在已有顺序之后。
- 达到目标商品数、达到最大页数、没有可点击的下一页页码/分页控件或用户停止时结束。
- 闲鱼当前搜索页常见的分页器没有“下一页”文字按钮，插件会读取当前页码并优先点击下一页码；如果页面使用无文字箭头，则回退到分页器右箭头。
- 搜索卡片不作为最终商品记录写入；它只用于补充待访问链接和预览信息。
- 搜索页接口只读取真实商品节点 `data.resultList[].data.item.main.exContent`；页面配置资源、组件 ZIP 和其它非商品响应会被过滤。接口商品只能按商品 ID 为同一张可见卡片补字段，不能把接口缓存顺序当作页面顺序，也不能追加页面上不可见的网络记录。
- 任务状态持续写入扩展本地存储，侧边栏重新打开后可以继续查看。
- 专用标签页每次进入详情页前都会校验页面类型和待采集商品 ID；如果仍停留在搜索页或链接不一致，会重试并记录失败。
- 搜索列表为空时会等待异步卡片渲染并重试；如果从未成功进入详情页，任务状态为“失败”而不是“完成 0 条”。
- 任务完成后结果仍先保持在任务快照中，用户可以独立导出本次结果，或一次性加入数据中心商品总表；店铺基础资料可以同步用于商品字段，但完整店铺评价仍由店铺页任务负责。

### 3.5 两种采集模式

#### 页面详情模式（RPA）

- 读取商品详情页已经渲染到页面的公开信息。
- 适用于详情文案、店铺信息、评价区域需要经过页面渲染或滚动后才出现的情况。
- 批量任务会自动打开详情页，用户不需要再按按钮；任务完成后可单独导出本次结果或加入商品总表。
- 受页面 DOM 结构变化影响，速度较慢，但流程直观、字段更容易核验。

#### 接口观察模式（API Observation）

- 观察当前闲鱼页面自身发出的、已经公开加载到浏览器的 JSON/接口响应。
- 只解析页面已加载的公开响应，不读取 Cookie、Token，不生成签名，不调用用户提供的第三方签名代码，也不向隐藏接口主动发请求。
- 在详情采集任务中，插件仍然会自动进入每个详情页，只是优先从该详情页的公开响应中取数；必要时再合并页面 DOM 中可见的信息。
- 详情页 API 观察结果会按当前详情 URL 的商品 ID过滤，推荐商品或其它响应中的商品不会被写入当前详情任务。
- 如果某字段没有出现在公开响应或页面中，则保留为空并在数据质量提示里标出；接口模式不是“保证所有字段都有”的捷径。
- 接口模式仍然导出相同的 Excel，并用 `dataSource` 标注 `network:detail`、`dom` 或合并来源。

### 3.6 Excel 导出与图片

- 导出文件为 `.xlsx`。
- 商品主表固定为 18 列，图片列使用真实图片对象，不显示“已嵌入”文字；商品标题仍作为内部文件名的一部分，但不单独输出为主表字段。商品导出和店铺导出是两个独立工作簿。
- 图片索引表包含商品与图片的一对多关系；店铺资料、店铺评价、评价图片在导出时合并为“店铺综合”表，内部仍保持独立对象以支持评价去重和增量更新。
- 真实图片下载后嵌入工作簿中的图片对象；同时保留原始图片链接用于追溯。
- 图片文件名组合：`商品标题_店铺名_商品ID_图序号.扩展名`，自动清理 Windows 不允许的文件名字符。
- 商品主表包含卖家账号页、地区、粉丝数、关注数、卖家商品数、店铺简介、开店时长、商品好评率和店铺评价数，方便把商品卖点与店铺经营表现放在同一行比较；商品多图全部进入“图片索引”表并嵌入真实图片，主表只展示第一张成功下载的主图。
- 图片下载失败不阻止整个 Excel 导出，失败原因写入图片索引表。
- 可按每个商品 3/5/10 张或全部商品图片导出，并设置商品图片上限；已加载的店铺评价图片不与商品图片共用该上限，会单独全部处理。

### 3.7 下载方式与设置

- 自动下载：任务完成后自动生成并下载 Excel，并显示完成通知。
- 手动下载：任务完成后只保留结果，用户在侧边栏点“下载 Excel”时生成文件。
- 文件名模板支持日期、商品数量和任务类型等变量；下载路径采用浏览器下载目录下的相对文件夹。浏览器本身决定绝对下载根目录。
- 用户可以选择是否在下载时显示浏览器的“另存为”窗口。
- 详情页任务会自动复用当前标签页访问卖家账号页，补充简介、开店时长、粉丝/关注、商品数和公开好评率等基础字段；完整店铺评价及评价图片仍应单独采集当前店铺页。详情页任务不会创建额外卖家标签页。
- 设置保存到扩展本地存储，新任务立即使用最新设置。

### 3.8 历史任务

- 保存任务类型、开始/结束时间、模式、目标数、成功数、失败数、结果快照和最后状态。
- 支持查看任务详情、重新导出和删除历史。
- 默认保留最近 30 天，最多保留 50 个任务，超出后按时间淘汰。
- 当前采集数据与历史任务分开管理：清空当前数据不会自动删除历史。

### 3.9 数据中心

- 数据中心提供“商品表”和“店铺表”两个独立页签，并分别显示数量和下载按钮。
- “加到数据中心商品表”只合并商品暂存结果；“加到数据中心店铺表”只合并店铺资料、评价和评价图片。
- 当前详情页、批量商品链接和搜索跨页任务都支持“加入商品表”与“单独导出”；当前店铺页支持“加入店铺表”与“立即下载 Excel”。

### 3.9 通知与状态

- 侧边栏内实时显示阶段、当前详情页、已访问数、成功数、失败数和剩余估计。
- 任务完成、停止或失败时在侧边栏显示明确结论。
- 若浏览器允许扩展通知，任务完成后弹出系统通知；通知内容包含成功数和失败数。
- 自动下载成功后再次提示文件名；下载失败时给出手动下载入口。
- 页面消息无响应时必须在有限时间内给出失败状态；不能让“采集当前详情”“采集当前店铺页”“批量采集”和“搜索跨页”一直显示为无反馈。
- 若历史任务超过 90 秒没有状态更新时间，系统自动将其标记为失败并释放全局任务锁；已保存的数据不删除，用户可以重新开始任务。

### 3.10 一键页面诊断包

- 在当前页面模块提供“一键导出页面诊断包”。
- 自动读取当前页面已经运行完成后的实时 DOM，而不是只读取 `view-source` 的初始 HTML。
- 同时整理可见文字、商品链接、图片地址、当前页面已经识别的商品记录和最近的公开接口响应。
- 对明显的 Cookie、Token、Authorization、签名和会话字段进行字段级脱敏；DOM 和可见文字仍可能包含页面公开显示的昵称或其它信息，用户上传前应快速检查。
- 尽量附带当前页截图，最终打成 ZIP 下载，供开发适配使用。

## 4. 用户界面原则

- 采用浏览器侧边栏作为主工作区，不把需要持续运行的任务放在一次点击就消失的弹窗里。
- 首页只展示功能分组入口；采集当前详情、批量链接、搜索跨页、数据、历史和设置各自进入独立页面。
- 返回按钮使用单层父级关系：一级功能页返回首页，任务页进入数据中心后返回任务页，避免在详情页和设置页之间循环跳转。
- 首页的产品说明放在功能入口之后，首次打开侧边栏时优先看到可以立即点击的操作。
- 任务运行时进入独立的处理任务页，显示进度环、任务概览、失败记录和导出入口。
- 设置独立成页，不打扰主采集流程；所有按钮都有禁用、处理中、完成和失败状态，失败信息必须说明下一步怎么做。

## 5. 数据边界与合规边界

本产品只处理用户在已登录浏览器中能看到的、页面已经公开展示或已经加载的商品信息。产品不处理私聊、手机号、地址、订单、账号密码、Cookie、Token、验证码、风控规避、批量主动调用隐藏接口或绕过访问限制。

用户应遵守闲鱼的服务条款、网站规则、版权和个人信息保护要求；导出的图片和文案只应在有权使用的范围内用于研究与内部分析。

## 6. 验收标准

### P0 必须通过

- 当前详情页点击采集后能反馈成功或失败，不能无响应；店铺页采集同样要显示评价读取数量和完成提示。
- 当前详情页显示采集成功后，加入商品表和导出按钮必须可点击；临时进入账号页、返回详情页或 URL 跟踪参数变化不能让按钮变灰。
- 搜索页跨页启动后不需要人工再点击，能按页码或分页控件自动进入下一页，逐个进入详情页并在达到目标/页数时结束。
- 搜索页同一页的访问顺序必须与用户看到的卡片顺序一致：从第一排左侧开始，逐排向下；网络接口响应先后不得改变该顺序。
- 批量链接能逐个进入详情页，搜索卡片不会被当成最终商品记录。
- 批量、搜索、当前详情和账号页遇到公开登录提示或延迟渲染时，会先关闭提示并等待关键内容；稳定等待超时要显示失败原因，不得导出全空字段。
- 当前详情页和批量任务都提供“加入商品总表”和“单独导出”两个结果出口，互不覆盖历史商品数据。
- 当前店铺页可以独立采集店铺资料、评价文本和评价图片，并生成不含商品主表的独立店铺工作簿。
- 独立店铺工作簿默认打开“店铺综合”工作表；评价条数与“已采集评价数”一致；评价图片文件名、状态、失败地址和真实嵌入图片均位于评价对应行。
- 商品主表和图片索引表都能生成，至少一张可下载图片会作为真实图片嵌入 `.xlsx`。
- 自动下载与手动下载设置生效；任务结束有完成提示。
- 扩展重载后不再出现“Receiving end does not exist”导致永久无响应；对于旧标签页会给出刷新/重试提示。

### P1 应通过

- 接口观察模式可以捕获详情页公开响应并合并到结果。
- 任务可以跨页运行，侧边栏关闭后重新打开能看到状态。
- 历史任务可以查看并重新导出。
- 下载文件名和图片名称可追溯到商品标题、店铺名和商品 ID。

### P2 优化项

- 字段选择器、并发数、断点续采、数据质量评分和导出模板。
- 更精确的闲鱼页面适配器和可视化字段缺失提示。

## 7. 当前已知限制

- 闲鱼页面路由、接口字段和图片 CDN 可能变化；解析器需要持续适配。
- 页面没有公开展示的店铺简介、开店时长或评价不能凭空补齐。
- API 观察模式只能使用浏览器实际收到的公开响应；没有收到的字段不会通过签名接口补取。
- 浏览器下载 API 的绝对根目录由浏览器设置控制，插件只能指定下载目录下的相对路径。
