# 闲鱼公开商品研究采集器｜开发进度

更新时间：2026-08-08
当前版本：0.5.11 开发中

## 1. 当前结论

产品已经从“弹窗里手工点一下”的原型，进入“侧边栏承载长期任务、Service Worker 负责自动编排”的重构阶段。当前最重要的修复不是再给按钮加一个提示，而是让 UI 与任务生命周期解耦：任务启动后由后台继续逐个打开详情页，界面只负责控制和展示。

本轮 0.4 重点是把侧边栏改成分层工作台：主页只展示功能入口，采集参数进入独立页面，任务处理和完成结果进入独立任务页，数据导出进入数据中心。同时移出了导致 Chrome 拒绝重新加载的诊断目录。

本轮 0.4.1 针对真实搜索页截图继续修复：搜索按钮被任务状态轮询误判为禁用、闲鱼分页没有“下一页”文字按钮、返回按钮历史栈不稳定，以及首页说明内容挡住主要入口。

本轮 0.5.0 根据实际导出 Excel 和评价诊断包继续修复：搜索任务必须真的进入详情页；商品主表改为用户指定的 18 列；修正账号页把店铺名称识别成“登录”的问题；新增当前店铺页、逐条评价和评价图片采集，并把店铺资料/评价拆成独立工作表。

本轮 0.5.0 收尾又修正了图片预算和评价懒加载：商品图片上限只作用于商品图，已加载的评价图片独立完整处理；评价区如果使用内部滚动容器，会优先滚动该容器；主表在第一张商品图失败时会自动选择同商品下一张成功图片。

本轮 0.5.0 又根据实际导出的 Excel 回归修正了好评率、粉丝/关注和店铺页直接导出；随后发现“店铺简介为 46”等问题不是数字格式问题，而是账号页异步渲染与宽泛 DOM 选择器造成的字段串位。

本轮 0.5.1 改为修复根因：账号资料必须在连续两次读取一致后才合并；简介只从账号资料区域的明确简介节点读取；商品数/评价数只从对应语义 Tab 读取；若已有明确 Tab 标题但没有其自身数量，则保留空值，不从整页随机数字补位。纯数字店铺简介会原样保留。

本轮 0.5.1 继续补齐详情属性：服务类商品的“服务类型”（例如“金融”）优先写入唯一的“类目”字段；商品图片或属性图片不作为统一字段来源。

本轮 0.5.2 根据《搜索页逐个详情页.xlsx》和店铺页截图追查到两个此前没有解决的根因：账号页的 `infoTop` 只包含昵称，旧实现把它误当成完整资料区，导致地区、粉丝、关注、简介全部落空；详情 DOM/API 合并时空值可能覆盖有效值，且详情属性标签会拆成单字，导致服务类型回退成内部 `categoryId`。本轮修复账号资料最小容器、拆字标签解析、非空合并和语义类目优先级，并新增当前店铺历史状态查询。

本轮 0.5.3 针对最新回归截图追查到任务生命周期问题：搜索任务显示“详情页 3/4、75%”时，后台正在等待第 4 个详情页的页面消息；旧消息监听器/接口观察异常没有调用回调，导致 `collecting` Promise 永久等待。侧边栏按设计会把唯一活动任务作为全局锁，于是当前详情、店铺页、批量链接和搜索入口同时变成不可点击，看起来像四个独立故障。修复包括后台/侧边栏/内容脚本消息超时、API 观察和详情采集异常兜底、旧任务自动恢复，以及对“ready-to-collect”漏闹钟的补排程。

本轮 0.5.4 根据最新 Excel 和“当前详情页/当前店铺页”反馈修复了三类根因：原开店时长正则在“1天前来过 | 来闲鱼239天”中用宽范围邻近匹配，可能错误捕获 1 天，现改为标签和值直接配对；简介和服务类型不再依赖整页随机数字或固定 class，而是在账号资料/详情属性语义块内识别，纯数字简介仍然合法；商品任务结果与店铺资料彻底隔离，任务先进入 `stagedItems`，当前详情、批量和搜索任务各自提供“加入数据中心商品表”和“单独导出”入口，店铺导出生成不含商品表的独立工作簿。当前详情页直接复用已打开的标签页，不再为补店铺资料新开标签页。

本轮 0.5.4 收尾又补了两个兼容性问题：账号资料作用域兼容 `description--*` 简介容器；旧版本任务没有 `stagedItems` 时，完成任务仍可按历史采集数量显示商品导出入口。当前详情/API 采集返回给侧边栏的结果改为使用后台已经按当前商品 ID/URL过滤后的记录，避免推荐商品混入“导出当前详情页”。

本轮 0.5.5 针对最新 `1.xlsx`、`3.xlsx` 和实际操作反馈继续修复：商品任务不再在详情采集后直接结束，而是强制执行“详情页 → 卖家账号页 → 下一商品/结束”的阶段，最后一条也必须完成店铺补采集；当前详情页的补采集复用原标签页并返回，不创建临时卖家标签页。商品工作簿只包含商品数据、图片索引和说明，店铺工作簿只包含店铺资料、店铺评价、评价图片和说明；首页数据中心增加商品表/店铺表两个独立入口；主表图片列改为真实图片对象，不再显示“已嵌入”，商品多图全部进入图片索引，评价图片按稳定的评价序号嵌入店铺工作簿。

本轮 0.5.6 针对“商品页明明有卖家账号入口，但商品表的卖家账号页仍为空”继续修复：真实 Chrome 商品页的卖家昵称位于一个 `item-user-info-nick--*` 节点内，其上层是带 `target="_blank"` 的 `/personal?userId=...` 链接；采集器现在优先从昵称节点向上找父级链接，再按卖家统计文本做兜底发现。详情页、批量链接和搜索跨页在结果缺少 `sellerUrl` 时都会重新向当前详情页查询 `GET_SELLER_ENTRY`，不会因为接口结果缺字段而跳过卖家补采集；当前详情入口也会对没有 `sellerUrl` 的有效商品结果发起补采集。代码级任务/Excel 烟测通过，真实 Chrome 的页面脚本读取在本轮出现超时，仍标记为待验收，不把超时误报为通过。

本轮 0.5.7 根据 `1.xlsx`、`2.xlsx` 和登录提示截图追到四个不同根因：搜索任务曾把 DOM 卡片与网络缓存按到达顺序混合，导致访问顺序不等于页面视觉顺序；详情页只等待浏览器加载完成，没有处理置顶登录对话框和延迟渲染，容易在字段尚未出现时读空值；当前详情补采集账号页往返及 URL 跟踪参数变化会触发侧边栏清空暂存结果，形成“提示成功但按钮变灰”；店铺工作簿虽然实际含有 78 条评价和 5 条评价图片记录，但默认打开第一张“店铺资料”表，用户很难看到评价。修复后搜索链接按屏幕纵横坐标逐排排序，网络只补同一可见商品字段；四类入口统一关闭公开登录提示并等待页面稳定；当前详情以真实结果行为成功标准并按商品 ID 保持按钮；有评价的店铺 Excel 默认打开“店铺评价”并在完成提示中明确评价/图片数量。

本轮 0.5.8 根据你的使用反馈调整导出形态：之前把店铺资料、店铺评价、评价图片拆成三个工作表，虽然内部结构清晰，但不利于逐行对照同行。现在导出时将三类数据合成为“店铺综合”一张数据表：一行一条评价，重复写入店铺资料字段，评价图片文件名、图片状态、失败地址和真实图片对象全部放在对应评价行；没有评价时保留一行店铺资料。工作簿只保留“店铺综合”和“说明”两张表，下载提示和数据中心说明同步更新。

本轮 0.5.9 根据你的进一步澄清修正导出结构：店铺资料不应与评价字段重复在同一张表。现在店铺工作簿严格只有两张数据表：“店铺资料”一店一行；“店铺评价综合”一条评价一行，并把该评价的图片文件名、下载状态、失败地址和真实图片嵌入同一行。工作簿不再额外生成“说明”页，默认打开店铺资料表，界面提示和数据中心下载名称同步更新。

本轮 0.5.10 只修复停止任务的异步竞态：点击停止时先登记任务取消令牌，再写入终止状态、清除任务闹钟并关闭采集专用标签页；已经在途的页面消息、导航回调和旧闹钟在返回后会校验任务 ID/状态，不能再把任务恢复成 `collecting` 或 `ready-to-collect`。原始搜索页不关闭，已采集的暂存数据和历史快照保留；侧边栏增加“正在停止”反馈，避免用户误以为按钮没有生效。

本轮 0.5.11 根据最新店铺导出 `3.xlsx` 和商品详情截图修正导出字段边界：商品主表新增“浏览数、想要数”，紧跟在商品文案后，并从详情页的“浏览/想要”标签或当前详情公开响应读取；店铺资料表移除“开店时长、商品好评率”，不再把店铺评价数量换算成百分比，也不再从商品补采字段混入店铺表。保留纯数字店铺简介的语义识别，不用字段格式限制来掩盖识别错误。

## 4. 当前风险

1. 闲鱼详情页路由和 API 响应结构可能变化，需要真实浏览器验收后补充适配器。
2. 某些图片 CDN 会拒绝扩展上下文的无凭据请求，可能需要使用页面已公开可读的响应或在可控范围内回退到页面上下文下载。
3. 浏览器扩展不能任意设置绝对下载目录；设置采用浏览器下载目录下的相对文件夹。
4. 接口观察模式只保证“观察页面已公开收到的数据”，不保证接口响应含有店铺简介、开店时长和评价全部字段；现在会按当前商品 ID过滤响应，店铺字段缺失时应单独采集当前店铺页。
5. 账号页公开评价需要页面实际加载到浏览器；如果闲鱼要求登录、延迟加载或临时限制，店铺页会显示已读取数量，不能把服务器显示的总评价数当成已成功读取数。
6. 店铺页评价图片可能使用 CDN 原图与缩略图两套地址，采集器优先使用评价内容的原图节点；CDN 拒绝扩展程序访问时会在“店铺评价综合”表的图片状态和失败地址字段显示原因。
7. 当前账号页诊断包来自其它卖家或旧版本页面时，不能证明新出现的字段串位已经覆盖；若修复后仍有错误，需要从实际出错店铺页重新导出诊断包，重点查看 `account-profile.json`。
