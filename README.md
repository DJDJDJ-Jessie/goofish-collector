# 闲鱼公开商品研究采集器

这是一个不依赖构建工具的 Chrome/Chromium MV3 扩展，面向“商业计划书、可研报告、标书、调研报告”等品类的公开竞品研究。主界面已经改为浏览器侧边栏，适合承载跨多个详情页的长期任务。

当前实现版本：`0.6.0`。

## 当前版本能做什么

- “采集当前详情页”只读取当前已经打开的商品详情页，不把搜索卡片当作最终商品记录；采集前会关闭遮挡页面的公开登录提示并等待详情内容稳定，采集详情后会复用当前标签页短暂进入卖家账号页补充基础店铺资料，再返回原商品页，绝不创建额外卖家标签页。只有真正返回了可导出的商品行才显示成功，成功后“加到数据中心商品表”和“导出当前详情页”保持可用。
- 商品页的卖家账号入口按真实页面结构识别：先找卖家昵称节点的父级 `/personal?userId=...` 链接，再从带“来闲鱼/卖出/好评率”等卖家统计的个人页链接中兜底发现；不再只依赖商品接口是否直接返回 `sellerUrl`。
- 打开商品详情页后点击一次，尽量补充商品文案、图片、类目、店铺名称、开店时长和商品好评率；服务类商品优先把详情属性区的“服务类型”（例如“金融”）写入唯一的“类目”字段。页面只提供平台内部 `categoryId`、没有公开类目名称时，类目留空，不把内部编号冒充类目。
- “采集当前店铺页”会读取店铺名称、账号页、地区、粉丝、关注、商品数、简介、评价数，并滚动评价区域读取当前页面可加载的全部公开评价；导出工作簿固定包含两张数据表：“店铺资料”一店一行，“店铺评价综合”一条评价一行。店铺页不生成无法可靠读取的“开店时长”和“商品好评率”，也不根据评价数量自行推算好评率。评价图片会下载并嵌入评价对应行，同时显示图片文件名、状态和失败地址；没有评价时“店铺资料”仍保留该店铺。页面会显示当前店铺是否已有历史记录、上次采集时间和评价数量；首次采集或更新完成后直接显示下载按钮，也可以进入数据中心。
- 在“批量商品链接”中粘贴多个商品详情链接后，插件会在专用标签页中逐个打开详情页；每次导航都会先处理遮挡页面的公开登录提示并等待真实详情内容稳定，再采集详情并进入对应卖家账号页补充基础店铺字段。最后一条也必须完成店铺补采集后任务才会结束。任务完成后可以把本次暂存结果加入数据中心，也可以只导出本次商品数据。
- 在“搜索页跨页采集”中设置目标商品数和最多页数后，搜索页只负责发现商品详情链接；商品严格按页面可见卡片的屏幕位置排序，即从上到下、同一排从左到右。接口缓存只能为同一个可见商品补字段，不能插入额外商品或改变顺序。插件会在专用标签页中逐个打开详情页、校验页面类型和商品链接，采集商品后进入卖家账号页补充基础店铺字段，再返回搜索页按当前页码点击下一页页码或分页控件。搜索列表尚未渲染出商品时会滚动并等待卡片稳定，不会把“0 条”直接标为完成。例如每页约 40 条、目标 100 条时，会跨约 3 个搜索页并访问 100 个商品详情页。
- 观察页面自身已经发出的搜索/详情 JSON 响应，作为 DOM 采集的补充。只发送响应中可识别的公开商品字段，不保存原始响应。
- 可以在侧边栏切换“页面详情模式”和“接口观察模式”。页面详情模式读取详情页已经渲染出来的文字、图片和店铺信息；接口观察模式只读取页面自身已经公开加载的 JSON/接口响应，再与页面内容合并。接口观察模式不直接调用闲鱼隐藏接口、不读取 Cookie、不生成签名；批量任务仍然会自动进入每一个商品详情页。
- 商品导出生成真正的 `.xlsx` 文件，包含“商品数据”和“说明”两个工作表；商品多图会在“商品图片、商品图片2、商品图片3…”列中嵌入同一商品行，不再生成图片索引表。店铺页导出生成独立工作簿，只包含“店铺资料”和“店铺评价综合”两张数据表，不会带出历史商品链接。首页“数据中心”也按商品表、店铺表分别展示数量和下载入口。
- 商品表默认顺序是：商品ID、商品链接、主图文件名、商品图片、商品文案、浏览数、想要数、价格、类目、店铺名称、卖家账号页、卖家地区、粉丝数、关注数、卖家商品数、店铺简介、开店时长、商品好评率、店铺评价数、采集时间；“商品标题”等可选字段不默认导出。设置页的字段工作台可以分别配置商品表、店铺资料表和店铺评价表，添加/移除字段并调整顺序，所有采集入口的下载都会使用已保存配置。浏览数和想要数只从当前商品详情页或该详情页已公开收到的对应字段读取，识别不到时留空。
- 浏览数和想要数会经过字段语义校验：`5.5万`会转换成整数 `55000`，没有单位的异常小数（例如 `55.00827`）会被拒绝，且会继续寻找同一详情页里真正显示的整数，不能让接口内部值抢占页面值；商品 ID 在导出时按文本保存，避免被 Excel 显示成科学计数法。
- 类目提取会按详情页所有候选属性容器逐一查找“服务类型/服务类目/服务类别”，不再只看第一个可能的详情容器；类目回退只使用明确的面包屑或标签行，不扫描推荐商品和通用 category 链接，避免把字段放错位置。
- 导出时下载图片并把真实图片二进制嵌入 Excel；商品多图按图片列嵌入商品主表同一行，评价图片嵌入店铺评价对应行，因此多图商品不会只保留一张图片。
- 图片文件名会按“商品标题_店铺名_商品ID_图序号.扩展名”生成，并在对应图片文件名字段中显示。
- 店铺评价图片按“店铺名_评价序号_图序号.扩展名”生成；“店铺评价综合”表在评价对应行显示文件名和下载状态，并直接嵌入真实图片；“店铺资料”表只保存店铺基本字段，便于单独筛选和比较。
- 商品图片默认按“全部（商品图最多 1000 张）”处理，也可以在侧边栏设置每个商品最多 3、5 或 10 张；已读取的店铺评价图片不与商品图共用这个上限，会单独全部处理。图片下载优先尝试原始地址和去除缩略图参数后的地址，默认保留原始 JPEG/PNG/GIF 二进制；只有浏览器无法直接解码或文件过大时才转换，最大处理尺寸从旧版 1600px 提升到 8192px，转换质量提升到 0.96。
- 支持任务完成后自动下载或手动下载；设置里可以填写浏览器下载目录下的相对文件夹、文件名模板、图片上限和“另存为”开关。
- 任务完成、停止或失败会在侧边栏显示结论；允许通知时会弹出系统通知。历史任务保存在本地，可重新导出或删除。
- 批量链接和搜索跨页任务会把详情页失败、店铺资料补采失败和核心字段待补充的链接统一记录在“处理任务”页；任务结束后显示“部分完成/失败”结论，并可一键复制失败链接，便于重新粘贴采集。
- “未成功链接”包含详情页/账号页真正失败和字段待补充两类情况。字段待补充只是质量告警，不等于闲鱼一定没有该字段；只有页面明确显示“暂无”或“未公开”时，才按页面未公开处理，否则保留为空并提示核验。
- 点击“停止任务”会立即标记当前任务为已停止，清除后续闹钟，关闭采集专用标签页，并阻止已经在途的异步页面响应恢复任务；原始搜索页不会被关闭，已经采集的数据仍然保留。
- 商品任务和店铺任务分开保存：商品任务暂存详情页商品结果，并可在自动访问卖家账号页后补入基础店铺字段；店铺任务单独保存店铺资料、全部已加载公开评价和评价图片。两类任务的导出、数据中心表和清空操作互不混用；店铺简介必须在账号资料语义区域中识别，不能用整页随机数字补位。商品详情任务中的开店时长/商品好评率是商品行的补充字段，不会回写到店铺资料表。
- 任务中心会持久化所有商品/店铺任务，而不是只保留一个“当前任务”：返回首页、关闭侧边栏或启动另一个任务后，仍可在任务中心查看每个任务的状态、进度、失败链接、暂停/继续和导出入口。店铺“采集全部商品详情”会先在店铺页发现商品链接，再在独立标签页逐个进入详情，并执行商品详情和卖家资料补采流程。
- 商品详情采集前会在详情文案语义区域查找“展开/展开全文/查看更多”等控件并点击后等待重新渲染，避免只读取折叠前的一小段文案。

## 数据中心

首页的数据中心包含两个独立表：

- 商品表：保存用户明确加入的商品详情结果，商品表 Excel 不包含店铺评价工作表。
- 店铺表：保存用户明确加入的店铺资料、评价和评价图片；导出时固定生成“店铺资料”和“店铺评价综合”两张数据表。“采集当前店铺页”完成后可以直接下载本次结果，也可以点击“加到数据中心店铺表”。

商品任务在详情页之后访问卖家账号页，只是为了补齐商品行的基础店铺字段，不会自动把只有首屏资料的半成品写入店铺表，也不会把不完整的店铺评价当成商品结果；需要完整店铺资料、评价和评价图片时，使用“采集当前店铺页”并点击“加到数据中心店铺表”。
- 页面消息现在有明确超时和异常回调：如果旧标签页、内容脚本或公开接口观察没有返回，任务会重试并记录原因，不会永久停在“处理中”；连续 90 秒没有进展的任务只会释放自己的闹钟和采集标签页，已经采集的数据保留，其它任务不受影响。
- 侧边栏提供“一键导出页面诊断包”，会自动提取当前动态 DOM、可见文字、商品链接、图片地址、规范化记录和经过字段脱敏的公开接口响应，打成 ZIP，方便后续精确适配闲鱼页面，不需要用户手动复制 F12。

## 安装

1. 使用 Chrome、Edge 或其他 Chromium 浏览器打开 `chrome://extensions/`（Edge 可打开 `edge://extensions/`）。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本目录 `D:\CodeSpace\goofish-collect`。
4. 登录闲鱼并打开 `https://www.goofish.com/`，点击浏览器工具栏里的“闲鱼研究采集器”图标，Chrome 会打开侧边栏。

当前项目根目录已经清理掉以下划线开头的诊断目录，Chrome 可以直接点击“重新加载”。诊断副本放在 `D:\CodeSpace\_diagnostic-review-20260806`，不属于扩展加载目录。

如果侧边栏提示 `Could not establish connection. Receiving end does not exist.`，先在扩展管理页点击“重新加载”，再回到闲鱼刷新当前标签页。侧边栏会尝试自动补注入内容脚本；如果仍失败，请确认当前标签页是 `https://*.goofish.com/`，而不是浏览器设置页、新标签页或其他站点。若之前的搜索任务因旧版本没有响应而卡住，重新打开侧边栏后最多等待 90 秒，插件会把旧任务标记为失败并重新启用采集入口；也可以进入“任务状态”手动停止它。

## 推荐使用流程

1. 在闲鱼搜索一个具体品类，例如“可研报告”“商业计划书”“投标书”。
2. 如果只研究一个商品，打开其详情页后在侧边栏点击“采集当前详情页”；按钮会先判断当前是否真的为详情页，完成后按需要点击“加到数据中心商品表”或“导出当前详情页”。
3. 如果有一批商品详情链接，把链接粘贴到“批量商品链接”文本框中；插件会逐个打开链接采集，完成后在“处理任务”页选择加入商品总表或导出本次结果。
4. 如果要按搜索结果批量研究，打开搜索结果页，在“搜索页跨页采集”中设置目标商品数和最多采集页数，再启动任务。搜索卡片只用于找链接，最终保存的是逐个打开后的详情页。
5. 如果要研究某个同行店铺，打开其 `/personal?userId=...` 店铺/账号页，在侧边栏点击“采集当前店铺页”，等待评价区域加载完成，然后直接点击“立即下载店铺 Excel”。这个文件只含“店铺资料”和“店铺评价综合”两张表，不会带出商品主表。
6. 需要换关键词时重复以上流程。可以在“下载设置”中选择自动下载，也可以在任务结束后手动导出本次商品结果。导出过程会先下载商品图片或评价图片，再生成 Excel，图片较多时需要等待一段时间。

## 重要边界

- 代码不读取 `_m_h5_tk` 等 Cookie，不生成闲鱼 API 签名，不主动调用隐藏 API。
- 代码不拦截 WebSocket，不采集聊天内容、私信或其他与竞品商品研究无关的数据。
- 代码不上传到服务器，采集结果只保存在浏览器扩展的本地存储里。
- 页面结构、接口字段和平台规则会变化；如果某个字段为空，通常意味着该字段没有在当前页面公开显示，或者页面结构已经变化。当前版本已针对账号页 `infoTop` 只包含昵称、其它资料位于兄弟节点的结构做了作用域修复，并在 DOM/接口合并时防止空值覆盖有效值。
- 当前版本不会把半成品当作无条件成功：详情页会等待商品文案、价格/图片和卖家入口等关键内容稳定；结束后若仍缺少图片、类目、卖家入口等核心字段，会在任务页列出对应链接和缺失字段，而不是静默导出空列。
- 店铺资料字段按页面语义区域读取：账号页会等待昵称、统计、简介等公开资料连续两次保持一致后才合并。店铺简介是用户自定义文本，纯数字也会保留；只有在账号资料区域明确找到的简介节点才会写入，不能用“是不是数字”代替字段识别。
- 店铺资料表不输出“开店时长”和“商品好评率”：当前店铺页不能可靠提供这两个字段，插件不会把评价数量换算成百分比，也不会用商品详情/账号补采字段冒充店铺页字段。
- 店铺页的“全部评价”以页面当前能加载到浏览器的公开评价为准；插件会自动滚动触发懒加载，但不会调用隐藏评价接口或猜测未公开内容。“店铺资料”保存店铺展示的评价总数和本次已读取评价数；“店铺评价综合”按评价逐行写入，便于核对页面展示的总数。
- 搜索列表页通常只展示标题、价格、缩略图、少量卖家信息；它在跨页模式中只作为“发现链接”的中间步骤，不会直接写入最终商品表。完整商品文案、商品页卖家信息来自逐个打开的详情页；每条详情采集后都会补采对应账号页的基础店铺字段，店铺简介和完整账号公开评价仍通过“采集当前店铺页”单独读取。
- 图片 CDN 如果拒绝扩展程序访问，会在导出提示中告知失败数量；如果在字段设置中选择了“图片状态”，Excel 还会写入具体失败原因。成功下载的图片会作为真实图片嵌入，而不是退回成只有链接。
- 为了避免一次导出占用过多内存，单次最多处理 1000 张商品图片；已读取的评价图片单独处理，异常页面最多保护性处理 20000 张。超出保护上限会在导出状态中提示。店铺评价文本和图片对象保存在扩展本地存储中，导出时按评价行嵌入。
- 使用时请遵守闲鱼的服务条款、 robots/访问规则和适用法律，保持人工触发、合理频率，不绕过验证码、登录限制、风控或访问控制。

## 要继续做精确适配，需要你提供什么

如果安装后“标题、价格、图片”能采集，但店铺/评价字段不完整，最有价值的是：

1. 一条搜索接口响应 JSON 的脱敏样本；
2. 一条商品详情接口响应 JSON 的脱敏样本；
3. 对应页面的截图，标出商品标题、价格、店铺简介、开店时长和评价所在区域；
4. 如果是店铺字段串位，请在出现问题的那个 `/personal?userId=...` 页面等待页面完全显示后，再点击“一键导出页面诊断包”。新诊断包会额外包含 `account-profile.json`，便于核对“解析出来的值”和实时 DOM 所属区域；优先提供一条出错店铺即可；
